# 検証結果

## 単体テスト

`npm test`: 22件成功。

作曲の6スタイル・12キー・32／64／96小節での再現性、入力の正規化、イベントの範囲・ソート、スウィング、パート間の独立性、曲の構造と終止を確認。
新しいピアノ・バンド編成については、全キー・全形式で音色指定とイベントの範囲を確認。4小節の旋律、対照的なテーマ、シードによる旋律の変化、強弱の増加、ピアノがギターの応答に余白を残すことも確認。
MIDIのヘッダー・テンポ・拍子・区間マーカー・音色・打楽器チャンネル、note-on/offの対応、同音の重なり、ミュート・音量を確認。
Web Audioの接続、ノイズのエンベロープ、パン、ミュート、発音終了前の無音、WAVのPCM構造、先読み再生・一時停止・位置移動・音声中断からの復帰を模擬コンテキストで確認。
ピアノ／ギターの倍音はそれぞれ独立したエンベロープを通って共有フィルターへ接続し、ピアノ・ギター・コントラバスの全ソースが指定パートを経由してミュートされることを確認。

## 実ブラウザ

Chromium 133で`npm run test:browser`成功。
PC 1365×920、スマートフォン相当390×844の両方でページエラーなし、横方向のはみ出しなし。
再生・一時停止、区間ジャンプ、ミュート／ソロ、テンポ入力、スタイル変更、再生成、MIDI／WAVダウンロード、連続生成、Service Workerによるオフライン再読込を確認。
再生成ボタンと演奏欄の「新しい曲」ボタンでシードが変わり、MIDIの楽器トラックに含まれる音符データも変わることを確認。曲名・コード名のメタデータは比較から除外。
指定したシードでの生成は、以前の曲とMIDIファイル全体のSHA-256が一致することを確認。スマートフォン相当のタッチ操作でも両方の再生成ボタンを確認。
Gardenia系・Ferris Wheel系の両方でも再生成後の音符の変化とシード再現性、楽器名とピアノロール凡例、初期テンポを確認。シードを含まないスタイル指定URLも確認。
